# Три параллельных потока по ЗАДАНИЕ.md

> Обновление 4 ноября: отдельные сессии создать не удалось, поэтому все потоки шли в одной сессии фоновыми агентами. Разделение по папкам сохранено. Итоги — в `для_облака/ИТОГИ.md`.

Задание: `для_облака/ЗАДАНИЕ.md`. Исходные данные: `для_облака/данные/`, их не менять.
Все пути в задании (`результаты/`, `движок/`, `прототип/` и т. д.) считаются от папки `для_облака/`.

## Кто что делает

| Поток | Блоки по порядку | Пишет только в эти папки и файлы |
|---|---|---|
| **1. Продажи** (исходная сессия) | A → B → C → J | `для_облака/результаты/` — `поставщики_75.xlsx`, `письма_30.*`, `конкуренты.md`, `ЖУРНАЛ_A/B/C/J.md`, `_работа/A_*`, `_работа/B_*`, `_работа/C_*`; `для_облака/продажи/` |
| **2. Данные и движок** | G → H → I → E | `для_облака/движок/`, `для_облака/цена/`, `для_облака/экономика/`; в `результаты/` — `анализ.xlsx`, `анализ.md`, `фильтр_закупок.py`, `ЖУРНАЛ_G/H/I/E.md` |
| **3. Продукт и правила** | F → D → K → L → второй круг F | `для_облака/прототип/`, `для_облака/реестры/`, `для_облака/контент/`; в `результаты/` — `правила.md`, `ЖУРНАЛ_F/D/K/L.md` |

Порядок внутри потоков сохраняет приоритеты задания:
- первыми идут A, G и F;
- вторыми — B, H и D (D нужен к четвергу);
- дальше остальные.

## Git

- Каждая сессия коммитит и пушит **в свою** ветку, ту, которую ей назначило приложение. В чужие папки не пишет. Тогда слияние в `main` пройдёт без конфликтов.
- Коммить примерно каждые 10 единиц работы, как просит задание.
- Если две сессии всё же попали в одну ветку, перед push делай `git pull --rebase`.

## Стыки между потоками

**G → F (сверка техзадания).** Поток 2 кладёт результаты в `для_облака/движок/демо_выход/<номер_закупки>.json`, в формате ниже. Поток 3 в первом круге F делает свои демо-данные **в том же формате**. Во втором круге он просто подставляет файлы из движка.

```json
{
  "закупка": {"номер": "", "предмет": "", "заказчик": "", "инн_заказчика": "", "закон": "44-ФЗ",
              "способ": "", "нмц": 0, "регион": "", "дата_окончания": "", "ссылка": "", "источник_документа": ""},
  "позиции": [
    {"№": 1, "наименование": "", "ктру": "", "окпд2": "", "количество": 0, "единица": "шт",
     "характеристики": [{"имя": "", "условие": ">=|<=|=|диапазон|из_списка|текст", "значение": "", "единица": "", "эквивалент_допускается": true}],
     "сверка": {"статус": "подходит|почти|нет", "товар_из_каталога": "", "артикул": "",
                "расхождения": [{"характеристика": "", "требуется": "", "у_товара": ""}]}}
  ],
  "итог": {"подходит": 0, "почти": 0, "нет": 0},
  "режим": "демо|живой"
}
```

**H → F (цена).** Поток 2 кладёт в `для_облака/цена/для_демо.json` таблицу ожидаемого снижения цены по нише, закону, способу и числу участников. Формат:

```json
[{"ниша": "", "закон": "", "способ": "", "участников": "", "медиана_снижения_%": 0, "p25_%": 0, "p75_%": 0, "n": 0}]
```

Поток 3 показывает эту таблицу в блоке «Цена» карточки тендера.

**E → F (фильтр закупок).** В первом круге поток 3 пишет свои правила «чистая поставка или работы/услуги». Во втором круге он может взять `результаты/фильтр_закупок.py` из потока 2.

## Окружение (проверено 3 ноября)

- Из контейнера закрыта сеть. ЕИС, rusprofile, checko, list-org, ГИСП и nousresearch.com не открываются ни через curl, ни через WebFetch: падают с DNS-ошибкой.
- Работает инструмент WebSearch: ссылки и сниппеты.
- Работают npm и PyPI.
- Блоки, которым нужны страницы и документы (A, C, D, G-шаг 1, K, F-дизайн, L), без расширенного доступа к сети работают только через поиск.
- Ключа Claude API в окружении нет. Поэтому G и F работают в режиме «демо» и «правила + регулярные выражения», а «живой» режим включается переменной окружения `ANTHROPIC_API_KEY`.
