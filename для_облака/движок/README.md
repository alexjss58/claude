# Движок сверки техзадания с каталогом (блок G)

Берёт техзадание закупки и каталог поставщика и по каждой позиции отвечает:
- 🟢 **подходит** — какой товар из каталога закрывает позицию;
- 🟡 **почти** — какой товар ближе всего и что нужно проверить или доконфигурировать;
- 🔴 **нет** — такого товара нет, или ближайший не проходит по неизменяемой характеристике.

Итог по закупке пишется в JSON в формате «G → F» из `ПОТОКИ.md`, чтобы его показал демо-кабинет (блок F).

Откуда берётся техзадание:
- **извещение ЕИС** (JSON или XML): характеристики там уже структурированы, разбор точный;
- **документ** docx, pdf, xlsx или txt: разбор по правилам и регулярным выражениям, а если задан ключ — через Claude API.

> Каталог `каталог_демо.xlsx` — **демо**. Это не прайс реальной фирмы. Модели и характеристики настоящие, взяты со страниц производителей; ссылка на источник есть в каждой строке. Цен нет.

## Быстрый старт

Нужен Python 3.10+ и пакеты `pandas openpyxl python-docx pdfplumber`. Пакет `anthropic` нужен только для режима Claude API.

Из папки `для_облака/`:

```bash
# одна закупка (извещение ЕИС) против демо-каталога
python -m движок.сверка движок/вход/eis/0813500000126020952.json --каталог движок/каталог_демо.xlsx

# все закупки из папок: JSON в движок/демо_выход/, читаемые отчёты в движок/демо_выход/читать/
python -m движок.сверка движок/вход/eis движок/вход/eis_xml движок/вход/eis_отложенная_проверка

# свой документ ТЗ (docx/pdf/xlsx/txt) и свой прайс
python -m движок.сверка путь/к/ТЗ.docx --каталог путь/к/прайсу.xlsx --выход результат/
```

То же самое из папки `движок/`: `python -m tz_engine <файлы или папки> --каталог каталог_демо.xlsx`.

Полезные ключи:
- `--столбцы` — показать, как распознаны столбцы вашего прайса;
- `--тихо` — не печатать подробности;
- `--режим правила|claude|авто` — по умолчанию `авто`.

## Режимы разбора

| Режим | Когда | Что делает |
|---|---|---|
| Извещение ЕИС | вход `.json` (из API ГосПлан) или `.xml` (ЕИС) | Берёт позиции, КТРУ, количество и условия («≥ 16 ГБ», диапазоны, перечни) прямо из структуры. Модель не нужна. |
| Правила | документ, ключа нет | Читает таблицы («Наименование характеристики | Значение | Единица») и свободный текст («Оперативная память не менее 16 ГБ»). |
| Claude API | документ и задан `ANTHROPIC_API_KEY` (или `--режим claude`) | Отправляет текст документа в Claude и получает строгий JSON по схеме. Модель по умолчанию `claude-sonnet-5-5`, другую задаёт `TZ_ENGINE_MODEL`. Нужен `pip install anthropic`. |

Ключ API в код не кладётся, только в переменную окружения:

```bash
export ANTHROPIC_API_KEY=...        # ключ из консоли Anthropic
export TZ_ENGINE_MODEL=claude-sonnet-5-5
python -m движок.сверка ТЗ.docx --режим claude
```

## Свой каталог (прайс)

Формат — xlsx или csv (разделитель `,` или `;`). Нужны столбцы:
- «Модель» или «Наименование»;
- «Категория»: ноутбук, системный блок, моноблок, монитор, мфу, принтер, коммутатор, ip-телефон, проектор, гарнитура, ибп, сервер;
- столбцы характеристик с единицей в заголовке: «Оперативная память, ГБ», «Диагональ, дюйм», «Скорость печати A4, стр/мин» и т. п.

Заголовки распознаются по смыслу («ОЗУ, Гб» → оперативная память). Полный шаблон столбцов есть в `каталог_демо.xlsx`. Пустая ячейка означает «нет данных»: такая характеристика попадёт в «проверить», а не в «не подходит».

## Выход

`демо_выход/<номер>.json` — строго формат «G → F» из `ПОТОКИ.md`. Все обязательные поля есть. Добавлены только необязательные поля, их можно не читать:
- `характеристики[].строго` — true для «более» и «менее» без «не»;
- `сверка.проверить` — характеристики, которых каталог не описывает (комплектация, габариты…);
- `сверка.причина` — почему выбран такой статус;
- `закупка.нацрежим_в_извещении` — в извещении есть ограничение или запрет на иностранные товары;
- `закупка.разобрано` — каким способом и когда разобрано.

Кроме того:
- `демо_выход/индекс.json` — список закупок с итогами (для списка в демо-кабинете);
- `демо_выход/сводка.csv / .xlsx / .md` — сводная таблица;
- `демо_выход/читать/<номер>.md` — отчёт по закупке человеческим языком (можно показывать на встрече).

Режим `"демо"` значит, что результат посчитан правилами без ИИ; `"живой"` — через Claude API.

### Как ставится статус

1. Категория позиции определяется по названию и КТРУ/ОКПД2. Берутся все товары этой категории.
2. У каждого товара проверяется каждая характеристика:
   - совпало;
   - не совпало;
   - в каталоге нет данных;
   - в каталоге нет такого столбца → «проверить».
3. **Подходит**: несоответствий нет, данные есть по всем сопоставленным характеристикам, и сопоставлено не меньше половины характеристик.
4. **Почти**: есть характеристики без данных, или не проходят 1–2 *настраиваемых* параметра (ОЗУ, накопитель, процессор, блок питания, ОС, опции).
5. **Нет**: товаров категории нет, или не проходит неизменяемая характеристика (цветность, формат, диагональ, порты, PoE, VESA, мощность…), или не проходят 3 и больше.

## Как добавить реальные закупки

1. **По номеру из ЕИС, через открытое API ГосПлан.** Ключ и регистрация не нужны, лимит 10 запросов в минуту:
   ```bash
   cd движок && python инструменты/получить_закупки.py 0813500000126020952 0272100000426000191
   ```
   Файл ляжет в `вход/eis/`. Контакты сотрудников заказчика удаляются.
2. **Документ ТЗ из ЕИС вручную.** Откройте закупку на zakupki.gov.ru → вкладка «Документы» → скачайте «Описание объекта закупки» (docx/pdf/xlsx) в `движок/вход/документы/` и запустите `python -m движок.сверка движок/вход/документы`. Старый формат `.doc` пересохраните в `.docx`.
3. **Чтобы посчитать точность на своих документах**, положите разметку в `эталон/<номер>.json` (формат — как у пяти готовых) и запустите `python -m tz_engine.evaluate`.

## Структура

```
движок/
  tz_engine/          код (латиницей — так надёжнее для инструментов)
    eis.py            извещение ЕИС (JSON ГосПлан / XML ЕИС) -> позиции и требования
    readers.py        чтение docx / pdf / xlsx / txt
    text_parser.py    разбор текста и таблиц правилами
    conditions.py     условия «не менее / не более / от–до / список / да-нет», сравнение
    units.py          единицы: ГБ/ТБ, ГГц, дюймы, Вт, ВА, мм, стр/мин, dpi…
    synonyms.py       категории и словарь «название характеристики -> столбец каталога»
    catalog.py        загрузка каталога, распознавание столбцов
    matcher.py        сверка и статус
    output.py         формат «G -> F» и отчёт в Markdown
    llm.py            режим Claude API (по ключу)
    evaluate.py       точность против эталона
    cli.py            командная строка
  сверка.py           вход «python -m движок.сверка»
  каталог_демо.xlsx / .csv   демо-каталог (58 моделей, 12 производителей)
  вход/
    eis/                       28 реальных закупок (JSON из API ГосПлан)
    eis_xml/                   3 реальных XML-извещения ЕИС (копии с GitHub)
    eis_отложенная_проверка/   8 закупок для честной проверки сверки
    документы_реконструкция/   docx/pdf/xlsx/txt, собранные из извещений (помечены)
    реестр_закупок.csv / .md   все реальные закупки: номер, заказчик, ссылка, откуда текст
  демо_выход/         JSON для блока F, сводка, отчёты
  эталон/             ручная разметка 5 закупок + 8 закупок отложенной проверки + результат_оценки
  инструменты/        получить_закупки, собрать_каталог, сделать_документы, реестр_закупок
  tests/              pytest
  отчёт.md            точность, ошибки, скорость, стоимость, что нужно до продакшена
```

## Тесты и оценка

```bash
cd движок
python -m pytest -q tests        # 49 тестов
python -m tz_engine.evaluate     # точность разбора и сверки -> эталон/результат_оценки.md
```

## Ограничения (честно)

- Настоящих docx/pdf заказчиков в работе не было: zakupki.gov.ru из облака закрыт. Документы в `вход/документы_реконструкция/` собраны из реальных данных извещений и помечены как реконструкция. Точность на «живых» docx нужно проверить на файлах, которые скачает Алексей (см. выше).
- Словарь сопоставляет около 75% формулировок характеристик ЕИС со столбцами каталога. Остальные идут в «проверить вручную».
- Каталог демо: у конфигурируемых ПК и ноутбуков производители не указывают ядра, кэш и TDP процессора, поэтому много статусов «почти».
