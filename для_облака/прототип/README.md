# «Тендер под ключ» — прототип сайта и демо-кабинета

Кликабельный прототип для созвонов с поставщиками и для разговора с банком. Это не макет, а рабочий сайт на демо-данных: лендинг и демо-кабинет поставщика из пяти разделов.

**Открыть без установки:** `dist/index.html`, двойной щелчок. Сайт собран в один файл, внутри уже лежат шрифты и данные. Сервер и интернет не нужны.

## Что внутри

| Экран | Адрес | Что показывает |
|---|---|---|
| Лендинг | `#/` | Что делаем, для кого, 5 шагов, отличие от Контура и Тендерплана, цифры рынка, условия пилота (гипотеза), форма «Хочу пилот» |
| I. Ваш ассортимент | `#/demo/assortiment` | Загрузка прайса .xlsx или .csv: поиск шапки таблицы, распознавание столбцов с правкой вручную, разбор характеристик |
| II. Подходящие тендеры | `#/demo/tendery` | 260 реальных завершённых закупок из выгрузки Тендерплана, только «чистая поставка». Фильтры: ниша, закон, сумма, регион, слова. Бейджи: «есть в ассортименте», «под своего?», «нацрежим», «мало конкурентов» |
| III. Карточка тендера | `#/demo/tender/<id>` | Сверка техзадания (зелёный, жёлтый, красный), нацрежим, цена (диапазон и маржа), риски. Разбор вставленного техзадания |
| IV. Черновик заявки | `#/demo/zayavka/<id>` | Таблица характеристик и шаблоны документов с пометкой «проверить юристом». Скачивание .docx и .csv |
| V. Сроки и деньги | `#/demo/sroki/<id>` | Шкала от подачи до оплаты: итоги, подписание, гарантия, поставка, приёмка, оплата. Расчёт денег в обороте |

Скриншоты всех экранов для компьютера и телефона лежат в `скриншоты/`. Принципы дизайна описаны в `design.md`.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install      # один раз
npm run dev      # разработка: http://localhost:5173
npm run build    # сборка в dist/ (перед сборкой сам подхватывает файлы блоков G и H, см. ниже)
npm run preview  # посмотреть собранную версию через локальный сервер
```

Проверки (нужен Playwright с Chromium):

```bash
node scripts/smoke_test.mjs   # 12 проверок: XLSX, фильтры, сверка, .docx/.csv, сроки, форма
npm run screens               # скриншоты всех экранов → скриншоты/
```

Если в системе установлен `@playwright/test` другой версии, укажите путь к браузеру: `PW_CHROMIUM=/opt/pw-browsers/chromium npm run screens`.

| `src/data/price_table_h.json` | Копия `../цена/для_демо.json` (модуль цены, блок H). Если файл есть, сайт берёт его, а не свою оценку | создаётся сам при `npm run build` |
| `src/data/sverka/*.json` | Демо-примеры сверки техзадания в формате «G → F» из `ПОТОКИ.md`. Позиции составлены для показа | `python3 scripts/make_demo_files.py` |
| `src/data/sverka_engine/*.json` | Копии `../движок/демо_выход/*.json` (движок сверки, блок G). Если там есть файлы, сайт показывает их **вместо** демо-примеров | создаётся сам при `npm run build` |
| `public/primer_praysa_orgtehniki.{csv,xlsx}` | Пример прайса на 47 позиций. Модели реальные, характеристики приблизительные, цены условные | `python3 scripts/make_demo_files.py` |

Все цифры рынка на сайте подписаны: «по данным Тендерплана, ноябрь 2026, оценка».

**Подключить настоящий движок (второй круг F).** Положите файлы в `../движок/демо_выход/`, затем выполните `npm run build`. Скрипт `scripts/sync_external.mjs` проверит формат, дополнит недостающие поля, пропустит битые файлы и напишет в консоль, сколько файлов подхвачено. Для проверки на своей папке: `ENGINE_DIR=/путь/к/папке npm run build`.

## Слой ИИ: «демо» и «живой» режимы

- **Демо (по умолчанию).** Ключи не нужны. Сверка берётся из подготовленных файлов. Вставленное техзадание разбирается простыми правилами (`src/ai/rules.ts`): строки вида «1. Ноутбук — 5 шт» и «Объём оперативной памяти: не менее 16 ГБ».
- **Живой.** Вызов Claude API (модель `claude-opus-5-5`) через официальный SDK `@anthropic-ai/sdk`, ответ в формате движка (структурированный JSON). Включается переменной окружения:

```bash
VITE_ANTHROPIC_API_KEY=sk-ant-... npm run dev
```

> ⚠ Vite вшивает такие переменные в код страницы, поэтому ключ увидит любой, кто откроет сайт. Это годится **только для локального теста на своём компьютере**. Не собирайте с ключом версию для GitHub Pages или Vercel. Для настоящего сайта вызов переносят на сервер (например, функция Vercel), а в браузер отдают только результат. Ключи в код не кладём.

## Выложить в интернет

Сборка — это один файл `dist/index.html` и два файла примера прайса. Адреса страниц идут через `#`, пути относительные (`base: './'`), поэтому сайт работает из любой папки.

### GitHub Pages
1. Соберите проект: `npm run build`.
2. Самый простой путь. Создайте отдельный репозиторий, например `tender-demo`, и положите в него содержимое `dist/`: `index.html`, `primer_praysa_orgtehniki.csv`, `primer_praysa_orgtehniki.xlsx`. Затем откройте Settings → Pages → Source: «Deploy from a branch», ветка `main`, папка `/ (root)`. Через минуту сайт появится по адресу `https://<логин>.github.io/tender-demo/`.
3. Путь через GitHub Actions в этом же репозитории. Добавьте workflow со стандартными шагами `actions/checkout`, `actions/setup-node`, затем `npm ci && npm run build` в папке `для_облака/прототип`, затем `actions/upload-pages-artifact` с путём `для_облака/прототип/dist` и `actions/deploy-pages`. В Settings → Pages выберите Source: «GitHub Actions».

### Vercel
1. Импортируйте репозиторий на vercel.com (New Project).
2. Root Directory: `для_облака/прототип`. Framework Preset: Vite. Build Command: `npm run build`. Output Directory: `dist`.
3. Переменную `VITE_ANTHROPIC_API_KEY` в настройках Vercel **не задавайте**: ключ попадёт в открытый код страницы.

Можно и без сборки на хостинге: `npx vercel deploy dist --prod` из папки прототипа.

## Честность и ограничения

- Поставщик «Пример-Оргтехника» вымышленный. Сверки помечены «демо, пример», заказчики в них условные.
- Закупки реальные, но завершённые (август–октябрь 2026). В рабочей версии в этом разделе будут открытые закупки.
- Цена — оценка по медианам, а не гарантия победы. Сроки — ориентиры, праздники не учтены.
- Документы — шаблоны: проверить юристом. Ничто на сайте не является юридической консультацией.
- Отзывов, логотипов клиентов и выдуманных цифр нет. Условия пилота помечены как гипотеза.
