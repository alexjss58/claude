# Тендер под ключ: клиентская версия

Пошаговый путь поставщика из 6 шагов (старт → компания → запрос → тендеры → ассортимент → анализ → цена). Один файл `dist/index.html`, без сервера и без внешних запросов. Рассчитан на телефон (iPhone) и компьютер.

## Запуск и сборка

```bash
npm install          # один раз
npm run dev          # разработка, http://localhost:5173
npm run build        # dist/index.html: один файл со всем внутри (шрифты, данные, код)
node scripts/smoke_test.mjs   # проход всего пути в Chromium, телефон 402×874 и компьютер 1440×900
```

`npm run build` сначала запускает `scripts/sync_external.mjs`, он собирает данные в `src/data/` (эти файлы генерируются, руками не править):

| Что | Откуда |
|---|---|
| тендеры | `data/снимок.json`, если нет — `data/_пример_снимка.json` (24 реальные закупки из демо-выхода движка, помечены «пример») |
| регионы | `data/регионы.json`, если нет — `data/_пример_регионов.json` |
| таблица цены | `../цена/для_демо.json` |
| демо-каталог | `../движок/каталог_демо.csv` (58 моделей) |

Скриншоты прохода smoke-теста лежат в `скриншоты/` (префиксы `телефон_`, `компьютер_`, `телефон_ИИ_`; с `DARK=1` ещё `тёмная_`).

## Как обновить снимок тендеров

1. Положите новый `data/снимок.json` (формат описан в задании и в `data/СНИМОК.md`; его готовит скрипт `scripts/обновить_снимок.py`).
2. `npm run build`. В консоли будет строка `[sync] снимок тендеров: data/снимок.json` и число тендеров. Если файл не подошёл (нет `тендеры` или `снято`), сборка возьмёт пример и напишет предупреждение.
3. Дата «Тендеры: снимок ЕИС на …» на стартовом экране берётся из поля `снято`.

Пример-снимок пересобирается командой `python3 scripts/make_example.py`.

## Как работает путь

- Состояние (шаг, ответы, ассортимент, отметки, цены, контакт) хранится в `localStorage` ключом `tpk.client.v1`, всё обёрнуто в try/catch. Перезагрузка не теряет прогресс. «Начать заново» стирает всё. Большой прайс, не влезший в localStorage, остаётся только в памяти.
- Шаг 3: фильтры ниша, регион/округ, сумма, подача не раньше «сейчас + 24 часа», ключевые слова по предмету и позициям. Закупки с флагом «работы/услуги» не показываем. Ранжирование: слова, наличие позиций, 3–14 дней до конца, свой регион выше; лицензии, ПО и услуги по названию штрафуются. Топ-5 отмечены, максимум 5.
- Шаг 4: Excel (.xlsx), CSV, вставленный текст или демо-каталог. Столбцы определяются сами; все «лишние» столбцы с данными считаются характеристиками товара. Ручной выбор столбцов появляется, только если наименование не нашли.
- Шаг 6: диапазон цены из таблицы `цена/для_демо.json` (ниша × закон × способ × участников). Предложение: от НМЦ·(1 − p75) до НМЦ·(1 − медиана). Участников по умолчанию: корзина, где набирается половина закупок ниши.

## Режимы сверки (шаг 5)

**Правила (работают всегда).**
- Вид товара определяется по названию позиции и коду ОКПД2 (ноутбук, МФУ, коммутатор…). Кандидаты — товары того же вида; бренд и модель из позиции повышают очки.
- Числовые условия (>=, <=, =, диапазон) проверяются по характеристикам товара, если они есть в прайсе; единицы (ГБ/МБ, ГГц/МГц, Вт/кВт) приводятся друг к другу. Не нашли характеристику: «проверьте».
- В прайсе нет характеристик (вставленный список): «≈ почти» и «в прайсе нет характеристик — проверьте: …».
- Нет структурных позиций (сейчас так у всех закупок снимка): сверка по названию предмета и кодам ОКПД2, виды товара вместо позиций, пометка «ТЗ в документах — сверка по названию, точнее после загрузки ТЗ».

**ИИ (Claude), если страница открыта на claude.ai.**
- Используется runtime-возможность `sample` (`sample.json`): один вызов на тендер; передаются позиции с характеристиками и до 10 кандидатов из ассортимента на позицию. Форма ответа проверяется; чего ИИ не вернул, добирают правила.
- Первый вызов спрашивает у человека разрешение, поэтому запускается только кнопкой «Начать анализ» / «Проверить с ИИ». При отказе (`not_granted`) ИИ скрывается; при `rate_limited` показывается сообщение «подождите», без повторов в цикле.
- Страницу надо публиковать с объявленными возможностями: `capabilities: {sample: {}, downloads: {}}`. Без объявления `sample` вернёт `not_declared` и работает только правила.
- На экране метка: «Сверка: ИИ (Claude)» или «Сверка: правила».

Сохранение CSV: на claude.ai через `downloads`, иначе обычная blob-ссылка (имя файла `tendery_itog.csv`).

## Куда подключить отправку заявки

`src/steps/Price.tsx`, функция `submit`, комментарий «ПОДКЛЮЧИТЬ ОТПРАВКУ». Сейчас заявка (контакт и согласие) лишь сохраняется в localStorage этого браузера и никуда не уходит.

## Что не работает и почему

- **Заявка «Хочу подать с вами» никуда не отправляется.** Нет сервера или бота, куда слать; только localStorage.
- **В снимке нет позиций и характеристик.** Поэтому в реальном снимке сверка идёт по названию и ОКПД2: максимум «≈ почти», «✓ подходит» появляется только с ИИ или когда у закупки есть позиции. Закрытие «X из Y позиций» точно считается только для закупок с позициями (так устроен пример-снимок).
- **Цены в демо-каталоге нет**, себестоимость вводится руками. Если в вашем прайсе есть цены, она считается по позициям «подходит» и «почти» × количество.
- **В таблице цены нет ниши «Компьютеры и оргтехника»** (и «Лабораторные реактивы» как отдельной): берётся ближайшая («Связь, аудио- и видеотехника», «Измерительные и лабораторные приборы»), в интерфейсе об этом сказано. Таблица цены строится по закупкам, это оценка, не гарантия.
- **Нацрежим** считается по таблице префиксов ОКПД2 из `src/lib/natreg.ts`; для кодов вне таблицы — «проверить по извещению». Это подсказка, не юридическая консультация.
- **Риски «бренд без эквивалента»** видят только предмет закупки, а не весь документ; обеспечение контракта читается, только если оно есть в снимке (в текущем снимке пусто).
- **Старый формат .xls не читается**: сохраните как .xlsx или .csv.
- **ИИ-режим проверен только на подделке `window.claude`** (smoke-тест `телефон_ИИ`). Живой `sample` на claude.ai в этой сессии проверить нельзя.
- Имя CSV-файла латиницей: кириллические имена скачиваемых blob-файлов в части браузеров теряются.
